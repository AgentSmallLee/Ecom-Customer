# 简历写法笔记：全栈项目的前后端表述

> 结论：**保持现有按系统能力分层的结构，末尾追加一行前端层**，不拆「前端篇/后端篇」。

## 为什么需要写前端

- 简历上写了"全栈独立开发"，面试官一定会考察前端工作量；现在五行清一色后端，"全栈"撑不住
- 前端有真实技术内容（手写 SSE 解析、轨迹可视化、记忆标识管理），不写浪费

## 为什么不拆成前后端两大块

- 现有「基础层/工具层/知识层/编排层/记忆层」按**系统能力分层**，技术纵深一眼可见，是这份材料的最大优点
- 拆成前后端两个板块会稀释 AI 工程浓度，变成平铺罗列
- 前端深度确实不及后端，写一行正好——写多了反而暴露短板

## 追加的前端层（建议写法）

```text
前端层：Vue 3 组合式 API 构建四模块客服工作台，fetch + ReadableStream 手写 SSE 流式解析，逐 Token 渲染与节点执行轨迹可视化；本地管理 threadId/userId 会话标识，配合服务端记忆实现刷新不丢、跨会话偏好召回
```

每个点都有真实代码对应，可防追问：

| 表述 | 对应实现 |
|---|---|
| 手写 SSE 流式解析 | `useChat/useGraph` 里 `getReader()` + 手动 split `data: ` 行 |
| 节点轨迹可视化 | GraphView 的 flow-trace（意图识别→订单查询→…执行链） |
| threadId/userId 管理 | 清空时换 threadId、userId 存 localStorage（记忆功能的前端配合点） |
| 逐 Token 渲染 | streamText 实时拼接 |

## 面试防追问：为什么手写 SSE 解析而不用 EventSource？

**EventSource 只支持 GET 请求**，而对话接口需要 POST（要带 message/threadId/userId 请求体），所以用 `fetch` + `response.body.getReader()` 手动读取流并解析 `data: ` 行。这是一个真实的技术取舍点，值得背熟。
