## 8. `withAuditContext` 完整调用链

**1. 入口：请求上下文注入**
`graph.service.ts:50-56` 生成 `traceId`，把 `{ thread_id, user_id, traceId }` 放进 `config.configurable`，全图节点共享。

**2. 意图路由 → 订单分支**
`intentRouter` 判定 `order` 意图后，LangGraph 调度执行 `orderAgentNode`。

**3. orderAgentNode：三件事**
- **a. 绑定用户工具**（`order-agent.ts:31-32`）：从 config 取 `userId`，`createOrderTools(userId)` 生成闭包绑定当前用户、带权限校验的工具。
- **b. 预设审计上下文**（`order-agent.ts:67-72`）：`model.withAuditContext({ source: 'graph-order-agent', traceId, userId, threadId })`。`withAuditContext`（`failover-chat-model.ts:143-155`）用不可变方式构造新 `FailoverChatModel` 实例，把 4 个字段写入实例私有属性 `defaultSource/defaultTraceId/...`。
- **c. 创建 agent 并执行**（`order-agent.ts:75-86`）：`createAgent({ model: modelWithContext, tools, systemPrompt })` 由 `langchain` 包构造 AgentExecutor，内部调用 LLM 时**对自定义 call options 的透传不可靠**，所以必须靠上一步把默认值写死在模型实例里。

**4. 模型调用：extractMetadata 四级兜底**
agent 内部触达 `FailoverChatModel._generate/_streamIt` → `extractMetadata`（`failover-chat-model.ts:567-608`），按优先级取 4 个字段：

| 优先级 | 来源 | 场景 |
|---|---|---|
| 1 | options 顶层 `source/traceId/...` | chat.service / agent.service 直接传 |
| 2 | `options.metadata` | LangChain 保留 metadata 的场景 |
| 3 | `options.configurable`（兼容 `user_id/thread_id`） | LangGraph 节点透传 |
| 4 | **实例默认值（withAuditContext 预设）** | createAgent 等无法透传的场景 |

**5. 写审计**
取到上下文后调 `writeAudit`（`failover-chat-model.ts:619-628`），异步不阻塞，写 `llm_audit_logs`。

**结论**：`withAuditContext` 就是给这条链补上「第 4 级兜底」。因为 `createAgent` 内部不保证把 `traceId/source` 透传到最终 LLM 调用，与其赌透传，不如把默认值烙进模型实例，`extractMetadata` 找不到就回退到它，审计日志永不漏写。其他分支不走 agent，直接用 `buildTraceConfig` 把字段放进 options 顶层，不需要 `withAuditContext`。

## 9. `BaseChatModel` 是什么？

**结论**：LangChain 的**聊天模型抽象基类**，来自 `@langchain/core/language_models/chat_models`（`failover-chat-model.ts:5`）。

**两层内容**：
1. **抽象方法（子类必须实现）**
   - `_generate()` —— 非流式：输入 `BaseMessage[]`，输出 `ChatResult`
   - `_streamResponseChunks()` —— 流式：输出 token chunk
   子类只需实现这两个**底层原语**，把厂商 API 的差异封装掉。
2. **免费获得的通用能力（基类基于抽象方法实现）**
   - `.invoke() / .stream()` —— 调用入口
   - `.pipe()` —— 与 prompt、输出解析器串联成链
   - `.bindTools() / .withStructuredOutput()` —— 工具绑定、结构化输出
   - `.bind()` —— 固定参数
   - 回调、重试、事件钩子等

**为什么关键**：`FailoverChatModel` 只要继承它并实现 `_generate` / `_streamResponseChunks`，就能自动获得所有高级能力。凡是接受 `BaseChatModel` 的地方都能接受 `FailoverChatModel`：
- `answer-synthesizer.ts:32-34` 里 `prompt.pipe(model).pipe(...)` 用 `pipe`
- `order-agent.ts:75-81` 里 `createAgent({ model })`，agent 内部还要 `model.bindTools(tools)`

**降级逻辑对上层完全无感**：调用方以为自己在用普通 ChatModel，实际内部已悄悄完成 primary → fallback → static 三级切换。这正是"继承抽象基类"带来的兼容性收益。
