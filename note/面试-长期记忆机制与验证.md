# 面试：长期记忆机制与验证

## 一句话结论

长期记忆基于 LangGraph 的 `BaseStore`（PostgresStore）实现，按 `userId` 命名空间存储，**跨会话、跨 threadId 共享**；短期记忆（checkpointer）按 `threadId` 存储，会话内有效。验证方式：跨会话说一个用户偏好，开新会话后问 AI 是否记得。

---

## 一、threadId 从哪来？

### 生成规则
- 前端生成：`crypto.randomUUID()`（标准 UUID v4）
- 示例：`a1b2c3d4-5678-90ef-ghij-klmnopqrstuv`

### 各页面的 threadId
| 页面 | 生成位置 | 生成方式 |
|---|---|---|
| ChatView | `useChat.ts` | `crypto.randomUUID()` |
| AgentView | `useAgent.ts` | `crypto.randomUUID()` |
| GraphView | `useGraph.ts` | `crypto.randomUUID()` |
| RagView | 无 | RAG 没有会话记忆 |

### 什么时候换新 threadId？
1. **首次进入页面** — 页面加载时生成一个
2. **点"清空"按钮** — 手动重置，生成新的
3. **刷新页面** — 存在 ref 内存里，刷新就没了（当前项目没有持久化到 localStorage）

## 二、两种记忆的区别

| 维度 | 短期记忆（Checkpointer） | 长期记忆（Store） |
|---|---|---|
| **存储介质** | PostgresSaver → `checkpoint` 表 | PostgresStore → `langgraph_store` 表 |
| **Key 格式** | `graph:{userId}:{threadId}` | `['memories', userId]` |
| **生命周期** | 同一会话内有效，换 threadId 就没了 | 跨会话持久，同一个 userId 永远在 |
| **内容** | 完整的对话消息历史 | LLM 提取的用户偏好/事实（结构化） |
| **写入时机** | 每轮对话自动写入 | 对话结束后异步写入（fire-and-forget） |
| **读取时机** | 每轮对话开头自动加载 | 每轮对话开头 recallMemories 节点召回 |

### 命名空间演进
```
// 早期：只有模块隔离
withNamespace('graph', threadId) → 'graph:threadId'

// 现在：模块 + 用户双隔离（防 IDOR）
withNamespace('graph', threadId, userId) → 'graph:userId:threadId'
```

## 三、长期记忆工作流程

### 写入流程（memory-writer 节点）
```
对话结束
  ↓
graph.service 异步调用 memoryWriterNode
  ↓
读取该用户已有的记忆（store.search）
  ↓
LLM 判断：哪些值得保留？哪些要新增？哪些该删除？
  ↓
store.put() 新增/更新  +  store.delete() 移除
  ↓
最多保留 MAX_MEMORIES = 10 条
```

### 召回流程（recall-memories 节点）
```
对话开始 → recallMemories 节点
  ↓
getStore(config) 拿到 store 实例
  ↓
store.search(['memories', userId], { limit: 10 })
  ↓
写入 state.userMemories
  ↓
后续节点（order-agent、rag、general-chat、answer-synthesizer）
通过 buildMemoryContext() 注入到 prompt 里
```

## 四、getStore(config) 为什么返回 undefined？

### 原因
store 没有被注入到图的运行时配置中。`getStore(config)` 从 `config.configurable.store` 里找，找不到就返回 undefined。

### 两处需要注入 store 的地方

| 场景 | 注入方式 |
|---|---|
| **图内节点**（recallMemories 等） | `graph.compile({ checkpointer, store })` 编译时传入 |
| **图外调用**（memoryWriter 异步副作用） | 手动把 store 塞进 config.configurable |

### 修复要点
1. `buildCustomerGraph(checkpointer, store)` 增加 store 参数，传给 `compile()`
2. `graph.service.ts` 的 `getGraph()` 把 `this.store` 传进去
3. 异步调用 `memoryWriterNode` 时，手动构造 `configWithStore`

## 五、验证长期记忆生效的方法

### 方法 1：看日志（最快）
后端控制台搜：
- `[memoryWriter] 用户 xxx 记忆更新：0 → 2 条` — 写入成功
- `[recallMemories] 召回 N 条长期记忆` — 召回成功

### 方法 2：查数据库（最准确）
```sql
-- 查某个用户的所有记忆
SELECT key, value
FROM langgraph_store
WHERE namespace[1] = 'memories'
  AND namespace[2] = 'U-dev-0001';
```

### 方法 3：跨会话验证（最完整）
**步骤：**
1. 打开 Graph 页面（threadId-1）
2. 说几句话包含明显偏好，比如 "我叫小王，我穿 L 码，对海鲜过敏"
3. 等后端日志出现 `[memoryWriter] ... 0 → N 条`（确认写入）
4. **点"清空"按钮**（换新 threadId）
5. 新会话里问："你知道我穿什么尺码吗？"
6. AI 能回答"L 码" → 生效 ✅

### 方法 4：看请求体（确认是新会话）
DevTools → Network → 看两次请求的 `threadId` 不一样 → 确实是跨会话了

## 六、常见坑

1. **不是什么都会被记住** — LLM 会判断"值不值得记住"，你好再见这种寒暄不会存
2. **写入有延迟** — memoryWriter 是异步的，对话结束后才在后台写，可能有几秒延迟
3. **最多 10 条** — `MAX_MEMORIES = 10`，满了以后 LLM 会替换掉不重要的
4. **同一个 userId 共享记忆** — 换 threadId 不换 userId，记忆还是同一份
5. **刷新页面也是新会话** — threadId 存在内存里，刷新就丢了（当前没做 localStorage 持久化）
6. **store 没传进去就是 undefined** — 节点里调 `getStore(config)` 返回空，记忆功能静默失效
