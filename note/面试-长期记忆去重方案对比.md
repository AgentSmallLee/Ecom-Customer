# 面试：长期记忆去重方案对比

## 一句话结论

当前项目用**确定性 key + LLM 全量重算**做去重，能防"完全重复"但防不了"语义相同表述不同"。更精准的方案是**向量相似度去重**，但要权衡成本和精度。

---

## 一、当前实现：确定性 key 去重

### 原理

```ts
const memoryKey = (text: string) => `m_${text.slice(0, 60)}`;
```

同一段文本生成同一个 key，用 `store.put()` 写入（upsert 语义：存在则覆盖，不存在则新增）。

### 能解决什么

- ✅ 用户说完全一样的话 → key 一样 → 不会重复存
- ✅ 第 N 轮对话还是同一条记忆 → key 一样 → 覆盖更新，不新增

### 解决不了什么

- ❌ "我喜欢红色" vs "我偏爱红色" → 两个 key → 存成两条
- ❌ "我穿L码" vs "我穿大号" → 两个 key → 存成两条
- ❌ 意思一样、说法不同的所有情况

---

## 二、LLM 全量重算的辅助去重

当前实现其实还有一层去重：**每轮 LLM 重新生成完整记忆列表**。

```
旧记忆列表（可能有语义重复）
    ↓
LLM 重新整理 + 合并相似的
    ↓
新记忆列表（更精简）
    ↓
diff 对比 → 旧的删掉，新的写入
```

LLM 会理解语义，把"喜欢红色"和"偏爱红色"合并成一条。

### 优点
- 不需要额外成本（本来就要调 LLM）
- 能处理语义级别的去重

### 缺点
- 不稳定：LLM 不一定每次都能准确合并
- 依赖模型能力：模型越聪明，去重效果越好

---

## 三、三种去重方案对比

| 方案 | 原理 | 精度 | 成本 | 实现难度 | 推荐度 |
|---|---|---|---|---|---|
| **确定性 key** | 文本完全一样才去重 | 低（精确匹配） | 零成本 | 简单 | ⭐⭐（基础防线） |
| **LLM 重算合并** | 每次让 LLM 重新整理列表 | 中（依赖模型） | 中（每次都要调 LLM） | 简单 | ⭐⭐⭐（当前主方案） |
| **向量相似度** | embedding + 余弦相似度阈值判断 | 高（语义级别） | 高（每次要调 embedding 接口） | 中 | ⭐⭐⭐⭐（精度要求高时用） |

---

## 四、向量相似度去重详解

### 流程

```
新记忆文本
    ↓
embedding 接口 → 向量
    ↓
和每条旧记忆的向量算余弦相似度
    ↓
相似度 > 0.85？→ 是同一条，更新旧的
            ↘ 不是同一条，新增
```

### 伪代码

```ts
async function upsertMemory(userId: string, newText: string) {
  const existing = await store.search(['memories', userId], { limit: 10 });
  const newEmbedding = await embeddings.embedQuery(newText);

  for (const old of existing) {
    const sim = cosineSimilarity(newEmbedding, old.value.embedding);
    if (sim > 0.85) {
      // 语义相近 → 更新旧记忆，不新增
      await store.put(['memories', userId], old.key, {
        text: newText,
        embedding: newEmbedding,
      });
      return;
    }
  }

  // 没有相近的 → 新增
  await store.put(['memories', userId], memoryKey(newText), {
    text: newText,
    embedding: newEmbedding,
  });
}
```

### 适用场景
- 用户量大、记忆数据多
- 对去重精度要求高
- 能接受额外的 embedding 成本

## 五、面试回答模板

> "长期记忆的去重，我们项目里用了两层机制。
>
> 第一层是**确定性 key**：同一段文本生成同一个 key，用 upsert 写入，完全重复的不会存多份。这个是零成本的基础防线。
>
> 第二层是**LLM 全量重算**：每轮对话结束，让 LLM 根据已有记忆和最新对话，重新生成一份完整的记忆列表。LLM 会自己合并语义重复的，比如"喜欢红色"和"偏爱红色"会合一条。然后和旧列表做 diff，新增的写入，消失的删除。
>
> 当然这种方式依赖模型能力，不是 100% 稳定。如果对去重精度要求更高，可以用**向量相似度**的方案：每条记忆存的时候算 embedding，写入前和已有记忆算余弦相似度，超过阈值就认为是同一条，更新而不是新增。这样能做到真正的语义级去重，但每次要调 embedding 接口，会增加成本和延迟，需要在精度和成本之间做权衡。
>
> 我们项目当前的场景是客服助手，记忆数量不多（最多 10 条），用 LLM 重算的方式基本够用，性价比最高。"

---

## 六、金句

- **确定性 key 防"一模一样"，LLM 重算防"意思一样"，向量相似度才是真正的语义去重**
- **去重没有银弹，要在精度和成本之间找平衡点**
- **记忆数量不多时，LLM 重算的性价比最高**
